# 机器学习阶段学习总结（Day 14–17）

## 1. 先定义预测问题，再训练模型

本项目预测“客户在首笔已送达订单之后的 90 天内，是否会再次产生已送达订单”。预测时点是首笔订单的送达时间；标签窗口是之后 90 天。只有完整经历 90 天观察期的客户才能进入样本，避免把“未来尚未观察到”误当成“不复购”。

## 2. 时间泄漏比模型复杂度更重要

特征只使用预测时点可得到的首单信息：商品数、商品金额、运费、支付金额、配送时长和品类数。评论、后续订单、最终 RFM 与未来标签都被禁止使用。数据按时间依次分为训练期、选择期、校准期和最终测试期；LightGBM 的早停集也仅从训练期末尾切出。最终测试集不参与任何拟合、调参或选模。

## 3. 类别不平衡下不能只看 Accuracy

90 天复购率约为 1.1%，即使模型始终预测“不复购”，Accuracy 也会很高但没有业务价值。因此项目使用：

- PR-AUC：关注少数正类的排序质量；
- Precision@K、Recall@K：只触达前 K% 客户时，命中了多少复购客户；
- Lift@10%：前 10% 人群复购率相对于全体平均复购率的倍数；
- Brier score：概率预测与真实结果的接近程度，只能用于合法概率，不能用于首单金额等原始排序分数。

## 4. 基线、模型比较与校准

首单商品金额是简单业务基线，它只提供排序，不能当作概率计算 Brier score。项目比较 Logistic Regression、Random Forest 和 LightGBM，以选择期 PR-AUC 为主、Lift@10% 为辅助选择指标。最终选中 Logistic Regression，说明在严格限制为首单特征的条件下，简单线性模型的时间泛化更稳定；复杂树模型并未带来足够增益。

选中模型再用独立校准期拟合 sigmoid 映射，把模型分数校准为可解释的复购概率。校准不应用于重新选模，最终测试集只评估一次。最终测试中，模型 PR-AUC 为 0.012274，高于首单金额规则的 0.009855；Lift@10% 为 1.226994，高于规则的 0.858896。提升真实存在，但绝对复购率仍低，模型适合做优先级排序，而不是断言客户一定会复购。

## 5. 模型解释与审计

模型产物保存特征 schema、校准器、指标、模型卡和代表客户预测。代表客户保留 `customer_key`，便于追溯。特征重要性只能说明模型中的关联，不说明因果影响；历史观察数据不能证明某项营销动作会导致复购。

## 6. 从预测到营销 ROI

Day 17 将校准概率转换为情景模拟。只计算营销带来的增量：

```
增量复购 = 被触达客户预测概率之和 × 假设提升率
净增量利润 = 增量复购 × 平均复购收入 - 触达成本
```

模拟器默认在多个预算中选择净增量利润最高的方案，而不是 ROI 最高的方案。若所有方案利润不大于零，业务上应选择暂不投放，而不是把“亏损最少”误称为最优方案。提升率是业务假设，必须以小规模随机 A/B 测试验证，不能从预测模型本身推出。

## 7. 可复用的方法论

1. 先确定 prediction time、可用特征和标签窗口；
2. 用时间顺序隔离训练、选择、校准和测试；
3. 建立简单业务基线，再比较模型；
4. 针对不平衡问题使用 PR-AUC 与 Top-K 指标；
5. 概率用于决策前先校准；
6. 把预测结果与因果营销效果明确区分；
7. 保存模型、特征、指标与代表样本，使实验可复现、可审计。
