# Olist 项目学习笔记汇总（Day 1–17）

**用途：** 这是一份按知识脉络整理的学习记录，而不是仅列出完成事项。每一阶段都记录“为什么这样做、错了会怎样、后续如何复用”。

## 数据工程与治理

项目从九张 Olist CSV 建立 `raw → staging → warehouse → marts` 分层。最重要的学习是先固定粒度再连接：订单商品与支付都是一对多，必须先分别聚合到订单，再计算收入和支付，避免金额倍增。有效业务订单统一为 `delivered`；客户身份用 `customer_unique_id`，而不是会随订单地址变化的 `customer_id`。数据质量不等于 CSV 行数正确，还需检查主外键、缺失、金额范围、订单状态与时间顺序。

原始层保留输入事实，staging 层统一类型、去重和异常标记，warehouse 层承载可复用的事实/维度语义，marts 层按分析问题输出固定粒度。这种结构的价值是：发现一个口径错误时可以定位在哪一层修正，不需要在每个图表中重复修补 SQL。

## 从拿到项目到形成可用数据集：实际推进顺序

### Day 1–2：先让环境可复现

拿到项目不能立刻做图。先用 `pyproject.toml` 固定 Python 依赖、用 `.env.example` 声明配置、用 Docker Compose 固定 PostgreSQL 版本与健康检查。这样换电脑或交给评审时，环境不会依赖“我本机正好装过什么”。验证不只看 Docker 图标，而是运行测试和 `pg_isready`；Docker Desktop 未启动、容器存在但数据库未就绪是两类不同问题。

### Day 3–5：先问数据“应当是什么”，再问它“现在是什么”

为九张 CSV 写数据契约：文件名、字段、主键和例外。`geolocation` 没有真正主键，因此不强行定义；这是尊重源数据而不是为了方便制造错误规则。导入前检查结构，导入时计算文件 SHA-256 并记录批次审计，重复文件跳过，实现幂等。质量报告检查主键、孤儿外键、负金额、未知状态和不可能时间；其意义不是宣称数据完美，而是把本次未发现的问题和规则范围写清楚。

### Day 6–7：确定粒度后才建仓库

先在 Navicat 验证每张表“一行代表什么”。订单一行一单，订单商品一行一件，支付一行一次订单内支付；它们不能同时直接按订单连接。正确路径是：商品先按订单聚合，支付也先按订单聚合，再连接到订单事实表。用订单数唯一性、商品金额总和、运费总和与支付金额总和作为不变量测试。产品类别缺失、翻译缺失、已送达但缺送达时间等异常保留并打标，不删除、不伪造。

### Day 8–10：把数据变成一致的业务语言

先建立指标字典，明确 GMV、商品金额、订单、活跃客户、新老客和复购的公式、粒度和过滤条件；然后建月度增长、Cohort、复购窗口、Customer 360 与 RFM 策略集市。遇到频次高度集中为 1 时，不使用看似精细的四分位；遇到边界月份或不足 90 天观察期时，不把未知未来当作 0。性能上，相关子查询慢时先减少扫描次数：预聚合客户的最早后续订单，再与多个窗口比较。

## 分析方法

月度增长将 GMV 拆成购买客户数、购买频次和客单价；Cohort 以首笔已送达订单月份分组，并用完整观察月标记避免把截断月误读为流失。RFM 采用 R、M 分位数和 F 的 1/2/3+ 稳定规则，因为约 97% 客户只有一笔订单，机械四分位会制造虚假精细度。比率汇总必须按分母加权，不能直接平均各州或各品类比例。

这部分的通用原则是：任何“率”都必须说明分子、分母和资格条件；任何时间趋势都必须说明是否包含不完整月；任何客户分群都要检查原始分布是否支持当前分箱规则。

## 统计推断

连续且偏态的评分差异使用 Mann–Whitney U；报告中同时给出样本量、中位数差、bootstrap 置信区间、秩二列相关和 p 值。延迟订单的评分中位数比按时订单低 3 分，秩二列相关为 -0.554，说明强关联；但品类、卖家、地区与时间等混杂未控制，因此不能称为因果。按时/延迟首购客户的 90 天复购率差为 -0.211 个百分点，95% CI 为 [-0.550, 0.128]，Fisher p=0.251，现有数据不足以证明复购率存在差异。

## Dashboard

Dashboard 的筛选器必须与集市粒度一致；页面不可假装应用一个数据集不支持的筛选。展示层把图表、表格和字段标签中文化，查询仍使用参数化 SQL、仓库接口和缓存。导航与页面只是展示，业务计算保留在服务层。

## 机器学习

预测目标是首笔已送达订单后 90 天是否再次已送达。预测时点是首单送达时间，特征仅包括当时可得到的六个首单特征；后续订单、评论、最终 RFM 均禁止使用。没有完整 90 天观察期的客户被排除，防止把未来未观察到误标成“不复购”。

样本按时间分为训练、选择、校准、最终测试四段；LightGBM 的早停集也仅从训练期末尾取得。类别极不平衡（总体复购率约 1.095%），所以不用 Accuracy 选模，而用 PR-AUC、Precision@K、Recall@K、Lift@10% 和 Brier score。首单金额是原始排序基线，不能被错误地当作概率计算 Brier。

比较 Logistic Regression、Random Forest 与 LightGBM 后，选择期选中 Logistic Regression。独立校准期的 sigmoid 校准将 Brier 从 0.240971 降至 0.011727，不改变排序。一次性最终测试中，模型 PR-AUC 为 0.012274，高于金额规则的 0.009855；Lift@10% 为 1.226994，高于规则的 0.858896；Brier 为 0.009785。模型有真实但有限的排序提升，适合有限预算下优先级排序，不适合承诺单个客户一定复购。

## ROI 与因果边界

ROI 模拟器只计算增量复购：`预测概率之和 × 假设 uplift`，再减去触达成本。利润最大化不等于 ROI 最大化；若全部预算方案均为负净利润，业务建议应是暂不投放。uplift 是待 A/B 测试验证的业务假设，预测关联或特征重要性均不等于营销动作的因果效果。
