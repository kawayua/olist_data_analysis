# Day 12–13：Dashboard 数据粒度、页面级筛选与业务叙事

Dashboard 的筛选器不能因为“看起来方便”就全局共享；它必须和查询数据集市的粒度一致。月度增长集市支持月份范围和不完整月份开关，因此增长诊断页只展示这些条件；Cohort 集市支持首购月和观察完整性，因此留存复购页只展示 Cohort 条件；商品页的品类条件只影响品类表现，不能假装同时过滤州履约或延迟评分。没有有效筛选维度的客户价值页直接说明其为统一快照下的全局 RFM 结果。这样可以防止页面出现“控件已选择、数据其实未变”的误导。

比例在州粒度汇总时不能直接相加。延迟率的正确分子是每州 `订单数 × 延迟率`，分母是总订单数；90 天复购率的正确分子是已复购首购客户数，分母是具有完整 90 天观察期的首购客户数。金额、订单数和客户数可以求和，但比率必须按原始分母加权。这个原则同样适用于各品类的 30/60/90 天复购率汇总。

为了支持业务设计文档而不伪造数据，本阶段新增了三个分析边界。`customer_value_analysis` 以 RFM 分群为粒度，给出客户、商品金额、购买频次阶段及其占比；其中“首购/二购/多购”描述可观测的已送达订单频次，不能被直接称作流失。`repurchase_behavior` 以首购品类和观察窗口为粒度，严格使用完整观察期客户作为 30/60/90 天复购率分母；`repurchase_intervals` 将下一单分入互斥的 0–30、31–60、61–90、91–180、181+ 天桶。`delivery_rating_analysis` 以相对预计送达天数分桶：本次检查中提前 7 天及以上的平均评分为 4.317，而延迟 8 天及以上为 1.736。这是履约体验风险的强关联线索，仍不能替代控制品类、卖家、区域和时间混杂因素后的因果分析。

视觉编码也必须服从问题：GMV、订单和购买用户量纲不同，因此 P1 采用三张上下排列趋势图而非共享一条 Y 轴；增长诊断把购买用户、购买频次和客单价作为可观察驱动趋势，避免将近似变化机械相加为精确归因瀑布图；品类或客户分群的气泡图明确规定 X、Y 和气泡面积各自对应的真实指标。每张图的标题、口径说明与空状态共同构成分析结论的一部分，而不是最后才添加的装饰。
