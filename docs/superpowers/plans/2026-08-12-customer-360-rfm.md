# Customer 360 RFM Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a reproducible customer-level mart containing RFM features, service metrics, a 90-day repurchase label, and explainable business segments.

**Architecture:** PostgreSQL owns the one-row-per-customer mart and computes all warehouse-derived measures without fan-out joins. Python owns deterministic RFM scoring functions so the business rules can be unit-tested; the SQL mart uses the identical documented thresholds. The mart build script drops and rebuilds only `marts` tables.

**Tech Stack:** PostgreSQL, Python 3.11+, pandas, pytest, ruff.

## Global Constraints

- Use only `order_status = 'delivered'` for behavioral features.
- Use `fact_orders.item_revenue` for monetary value; never join payment and item detail tables directly.
- One row in `marts.customer_360` represents one `warehouse.dim_customer.customer_key`.
- A 90-day label is available only when the full observation window exists.
- Preserve the existing raw, staging, and warehouse layers.

```python
def score_recency(values: pd.Series) -> pd.Series:
    p25, p50, p75 = values.quantile([0.25, 0.50, 0.75])
    return pd.Series(
        np.select(
            [values <= p25, values <= p50, values <= p75],
            [4, 3, 2],
            default=1,
        ),
        index=values.index,
    )
```
