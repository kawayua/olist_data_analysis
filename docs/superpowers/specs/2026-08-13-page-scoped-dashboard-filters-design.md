# 页面级筛选与 Dashboard 体验优化设计

## 目标

移除所有页面共享的全局筛选器。每个分析页面只展示能够实际改变其数据查询结果的条件，使筛选语义、数据粒度与页面叙事一致；同时统一页面阅读顺序和反馈体验。

## 设计决策

采用“页面级局部筛选”方案：筛选区位于页面标题和 KPI 之间，采用展开的容器呈现，显示本页筛选范围说明。首页不放筛选器，作为全局概览和分析导航入口。

不采用保留全局侧边栏并禁用无效条件的方案：即使有解释文字，也会让用户误以为条件影响了数据。也不为现有全局聚合集市临时补充不支持的筛选维度：这会扩大当前 Dashboard 改造范围，且需要先定义新的数据粒度和口径。

## 页面与筛选契约

| 页面 | 可用筛选器 | 不展示的筛选器 | 数据口径 |
| --- | --- | --- | --- |
| 首页 | 无 | 日期、州、品类 | 全局州表现摘要和导航 |
| 经营总览 | 客户所在州 | 日期、品类 | 客户收货地址州 |
| 增长诊断 | 开始月份、结束月份、包含不完整月份 | 州、品类 | 全局月度增长 |
| 留存与复购 | Cohort 首购月份范围、包含不完整观察月 | 州、品类 | 全局 Cohort 留存 |
| 客户价值 | 无 | 日期、州、品类 | 统一快照时点下的全局 RFM 分群 |
| 商品与履约 | 商品品类 | 日期、州 | 商品表现按品类筛选；履约汇总保持全局口径 |

每个筛选器必须经过 `AnalyticsFilters` 转换并作为缓存函数参数；页面不得直接拼接 SQL 或创建数据库连接。

## 体验与信息层级

页面采用一致的阅读路径：页面标题和口径说明、局部筛选区、KPI、主图或主表、解释或行动建议。筛选区使用清晰标签和辅助文案说明“该筛选器影响什么”；没有筛选器的页面以数据快照说明替代筛选区。

空状态显示当前页面的有效筛选维度和可执行的恢复建议。图表关键数值和 KPI 不依赖悬停才能理解；图表下保留简短口径说明。页面保持窄屏下筛选器、KPI、图表按垂直顺序阅读，不要求水平滚动。

## 汇总指标正确性

州未筛选时，经营总览与首页的金额、订单和客户数可以加总；比例不可以直接相加。延迟率必须按订单数加权，90 天复购率必须按满足观察期的首购客户数加权。选择单个州时，直接使用该州原始比例。

## 组件边界

`app.components.filters` 从单一 `render_filters` 拆分为小型页面专用渲染函数，例如州、月份、Cohort 和品类筛选。共享的筛选值对象和向仓库过滤器的转换逻辑保留在该模块中，以避免重复数据契约。

`app.components.presentation` 或 KPI 组件提供州表现加权汇总的纯函数，便于用 DataFrame 单元测试；页面只负责调用和展示。布局、KPI、图表和洞察组件继续复用，不在页面间复制样式代码。

## 错误处理与验证

测试覆盖每类页面筛选器仅产生预期的 `AnalyticsFilters` 字段，且页面不再引用通用 `render_filters`。新增州汇总测试，验证两个州的比率按分母加权而非直接求和。保留现有 SQL 参数绑定测试、图表测试和页面存在性测试。

验收时逐页检查：只显示本页有效筛选器；筛选后的 KPI 和图表同步变化；空状态能说明恢复方式；首页和客户价值没有无效筛选器；未选择州时的比例在合理范围内。
