# Olist 项目阶段性后期报告

**报告性质：** 本报告不是最终结项报告。它确认数据分析、Dashboard 与机器学习阶段已完成，并列出仍占约 10% 工作量的 Agent、部署与最终交付。

## 一、项目定位与当前判断

项目按“70% 数据分析、20% 机器学习、10% Agent”组织。前两部分已从数据导入、质量审计、分层仓库、指标集市、统计分析、Dashboard，一直推进到可审计的复购模型和营销模拟。当前不是简单的页面原型：主要结论均绑定数据口径、SQL 集市、测试和限制说明。剩余工作不应被低估，因为 Agent 需要同时解决工具权限、SQL 安全、答案准确性、评测和部署复现。

## 二、阶段成果如何连接

数据工程层将九张源表变为稳定的订单、客户、商品和支付事实/维度结构；分析层用受治理的 marts 提供增长、Cohort、RFM、履约和复购指标；Dashboard 只读访问仓库并将字段中文化；ML 层另建首购时点特征，避免从 Customer 360 快照泄漏未来信息；ROI 层只消费校准概率和业务假设。这样的分层让同一个“90 天复购”在 SQL、图表、模型和模拟器中保持同一口径。

## 当前成果

项目完成了从数据质量、指标治理、客户增长与留存分析，到统计检验、交互式 Dashboard、概率模型和资源约束模拟的闭环。机器学习严格区分预测、校准与因果解释：最终测试显示模型相对首单金额规则有小幅排序提升，但 ROI 页面不将自然复购误算为营销收益。

## 三、当前局限与项目风险

Olist 是历史快照，缺失实际营销曝光、优惠、成本、库存和毛利，ROI 只能做假设情景，不能成为投放承诺。低复购率限制了模型绝对精度；数据时间停在 2018 年，存在分布漂移风险。统计分析大多为观察性比较；在未控制混杂或随机分配前，不能写成因果结论。模型与 ROI 页面已将这些边界明确展示，后续 Agent 也必须继承这些限制说明。

## 风险与下一阶段原则

Agent 不得绕过现有仓库接口或直接执行用户 SQL；必须使用白名单工具、参数验证、SQL AST 校验、最小只读权限和显式评测。真实大模型 API 评测应通过单独命令触发，CI 使用 fake client，避免自动产生费用。最终项目报告只有在 Agent 安全、评测和可复现部署完成后才可称为结项报告。
